VodaLens AU 0.1.3 improves sign-in safety, release integrity and refresh performance.

- The Android login handoff sends no token back into JavaScript. A transaction-bound commit reply lets the originating page compare its own copy, with navigation and timeout guards.
- Sign-in navigation checks cover document POSTs and subframes, and the login screen survives additional window and theme configuration changes.
- Recent-app previews are hidden. New Android Keystore keys explicitly use AES-256; existing encrypted data stays compatible.
- Rate limits retain the saved connection for retry. Ambiguous renewal outcomes continue to require reconnection so a potentially rotated token is not replayed.
- Disconnect clears local data and attempts Vodafone's advertised revocation endpoint. The confirmation explains that revocation may affect other sessions for the same Vodafone web-client grant.
- Independent reads run with a shared concurrency cap. Frequently reused chart/history derivations and date formatters are cached, and release builds skip debug-log construction.
- Browser-to-backend renewal research is disabled by default and requires explicit local opt-in plus one-time arming.
- Release builds validate the Gradle wrapper and pinned distribution checksum before accessing signing secrets. Protected release tags, full-history Gitleaks scans, stronger publication checks, MIT licensing and security reporting guidance are included.
- The optional Docker runtime is digest-pinned and excludes backend tests.

Requires Android 16 or newer. Carrier reporting delays and historical availability still apply; multi-day session lifetime remains unmeasured. This independent companion is not affiliated with Vodafone.

Download `VodaLens-0.1.3.apk` and use `SHA256SUMS` to verify it. The public APK keeps the public-release certificate used by v0.1.2. Personal/development builds use a different certificate; Android cannot update across certificates without uninstalling the old build and losing its local data.
